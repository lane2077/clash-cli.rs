# clash-cli 架构设计 v0.3

## 1. 核心目标

平台：Linux 与 macOS；内核：mihomo。

设计优先级：

1. 状态变更安全、可恢复。
2. Machine Contract 低歧义、可验证。
3. 人类 CLI 简洁自然。
4. 平台差异藏在深模块/适配器后面。

## 2. 两层接口

### 人类 CLI

默认中文文本，允许合理默认值、交互提示、自动 sudo 和 `setup` 一键编排。stdout 是否连接 TTY **不会改变格式**。

### Machine Contract

显式 `--machine` 开启，协议版本 `clash.machine/v0`。

- 无隐式环境开关。
- 无自动 sudo。
- 无浏览器打开、无限日志流、setup 黑盒编排。
- action 名唯一且 canonical。
- 写操作目标有歧义时要求显式参数。
- 输出统一 envelope；业务模块不生成协议元数据。

## 3. 模块边界

- `cli.rs`：语法、canonical action、machine 支持范围与输入约束。
- `lib.rs`：建立 machine context 后分发。
- `machine.rs`：协议、错误码、effect 与自描述。
- `output.rs`：Machine Contract 唯一序列化边界。
- `profile.rs`：订阅生命周期与 runtime 合成。
- `api.rs`：mihomo external-controller。
- `proxy.rs`：终端代理状态；顶层 `env` / `system` 的应用层实现。
- `system_proxy.rs`：桌面系统代理平台适配器。
- `service.rs`：systemd / launchd。
- `tun/`：TUN 策略、诊断、状态。
- `core.rs`：内核资产下载、SHA256、版本软链。
- `ui.rs`：Web UI。

## 4. canonical 命令面

```text
contract
ui
mode
sub
proxy
system
tun
env
core
service
api
setup   # human-only orchestrator
update
```

不提供 `profile`、`proxy env`、`proxy system` 等同义入口。

`proxy start/stop/status/auto` 仍是隐藏的人类终端便利动作，但不属于 machine capability。

## 5. 配置与状态

默认布局：

```text
$CLASH_CLI_HOME/
  profiles/index.json
  profiles/<name>.yaml
  profiles/mixin.yaml
  runtime/config.yaml
  runtime/tun.state
  core/versions/<tag>/mihomo
  core/mihomo -> versions/<tag>/mihomo
  core/current.meta
  proxy.state
  proxy.env
  system-proxy.state
```

唯一 runtime 写入路径：

```text
subscription + mixin overlay -> render -> runtime/config.yaml
```

`tun on/off` 只修改 mixin，再复用同一合成管道。

## 6. 状态层次

任何涉及系统的功能都区分：

- desired：命令要求的状态；
- committed：文件/配置已提交状态；
- runtime：进程/service 状态；
- observed：系统接口实际观测状态。

例如 launchd `print` 成功只代表 job 可查询，不等于进程 `running`；macOS 动态 utun 无法确认时必须返回 unknown/null，而不是猜 true。

## 7. Machine Contract

统一 envelope：

```json
{
  "contract": "clash.machine/v0",
  "ok": true,
  "status": "success",
  "action": "sub.list",
  "effect": {
    "state_changed": false,
    "verified": true
  },
  "data": {},
  "error": null,
  "meta": {
    "cli_version": "0.3.0",
    "platform": "macos",
    "arch": "aarch64"
  }
}
```

完整规范见 `机器契约-v0.md`，运行时可通过：

```bash
clash --machine contract
```

## 8. 人类 orchestrator 与原子 machine action

`setup init/unify` 一次跨越下载、订阅、render、service、UI、TUN，适合人，不适合 agent。Machine Contract 明确拒绝 `setup.*`；agent 应按需要依次调用 `sub.add → sub.fetch → sub.render` 等原子动作并检查每步 envelope。

## 9. 安全边界

- 订阅先校验后提交，异常响应不得覆盖旧配置。
- active 与 runtime 来源必须一致；失败切换不提交 active。
- shell export 值必须转义。
- 系统代理首次接管保存原状态，关闭时恢复。
- 自更新/内核安装缺少可信 SHA256 时拒绝执行。
- machine 永不自动 sudo。
- 测试永不真实执行 TUN 或系统写操作。
