# Machine Contract v0

协议标识：`clash.machine/v0`。

## 1. 开启方式

唯一开启方式：

```bash
clash --machine <command> ...
```

不会因为 stdout 被管道、子进程或 agent 捕获而自动开启，也不存在环境变量开关。

## 2. Envelope

每次 machine 调用 stdout **恰好一个 JSON 对象**：

```json
{
  "contract": "clash.machine/v0",
  "ok": true,
  "status": "success",
  "action": "sub.list",
  "effect": {
    "state_changed": false,
    "verified": true
  },
  "data": {},
  "error": null,
  "meta": {
    "cli_version": "0.3.0",
    "platform": "macos",
    "arch": "aarch64"
  }
}
```

失败时进程退出非 0：

```json
{
  "contract": "clash.machine/v0",
  "ok": false,
  "status": "failed",
  "action": "sub.fetch",
  "effect": {
    "state_changed": false,
    "verified": false
  },
  "data": null,
  "error": {
    "code": "PROFILE_NOT_FOUND",
    "message": "订阅不存在: main",
    "retryable": false
  },
  "meta": {}
}
```

## 3. status

- `success`：动作本身成功完成。
- `partial`：已发生部分状态变更，但后续步骤/验证失败；不能当作完全成功。
- `failed`：命令失败。

## 4. effect

`state_changed`：

- `false`：已知没有改状态；
- `true`：成功动作确实改变了状态；
- `null`：失败发生在外部系统操作中，无法安全断言是否有部分副作用。

`verified`：

- 只读/观测命令通常为 `true`；
- 写操作默认 `false`，除非实现明确执行了 postcondition 验证。

业务状态是否完整可验证仍由 `data` 表达。例如 macOS TUN 动态接口无法确认时，`data.runtime.interface_verified=false`。

## 5. 错误码

当前稳定错误码：

- `CLI_ARGUMENT_INVALID`
- `EXPLICIT_INPUT_REQUIRED`
- `RUNTIME_CONFIG_REQUIRED`
- `UNSUPPORTED_MACHINE_ACTION`
- `PROFILE_NOT_FOUND`
- `PROFILE_ALREADY_EXISTS`
- `PROFILE_NOT_READY`
- `PROFILE_INVALID`
- `STATE_CONFLICT`
- `PERMISSION_REQUIRED`
- `NETWORK_ERROR`
- `CHECKSUM_MISMATCH`
- `SERVICE_OPERATION_FAILED`
- `CONFIG_INVALID`
- `FILE_IO_ERROR`
- `UNSUPPORTED_PLATFORM`
- `NOT_FOUND`
- `INTERNAL_ERROR`

关键业务分支必须使用类型化 `CodedError`；`INTERNAL_ERROR` 是未完成迁移或未知故障的兜底，不应被调用方解释成可重试。

## 6. canonical action

机器动作只有一套命名空间。常用动作：

```text
contract.describe
sub.add / sub.list / sub.fetch / sub.remove / sub.render / sub.validate
sub.mixin.show / set / unset / reset
proxy.list / proxy.switch
system.on / system.off / system.status
env.on / env.off
mode.get / mode.set
tun.doctor / tun.on / tun.off / tun.status
core.install / core.upgrade / core.version / core.path
service.install / uninstall / enable / disable / start / stop / restart / status / log
api.*
update.check / update.run
```

完整列表直接查询：

```bash
clash --machine contract
```

## 7. human-only

Machine Contract 故意拒绝：

- `sub.update`：拉取 + render + restart 的人类快捷流程；
- `sub use`：render + restart 的人类快捷流程；
- `sub add --fetch`：登记 + 拉取的人类快捷流程；
- `setup.init / setup.unify`：跨多个子系统的一键黑盒；
- `ui.open`：桌面交互；
- `service.log --follow`：无限流；
- `proxy start/stop/status/auto`：终端便利状态，不是 agent 能力。

## 8. 推荐的 agent 订阅流程

```text
sub.add --name X --url ...
  -> sub.fetch --name X --force
  -> sub.render --name X
```

`sub.render` 成功写出 runtime 后才同步 active，因此 active 与 runtime 来源不会分叉。`sub.use` / `sub.update` 只服务人类快捷操作，不属于 Machine Contract。

## 9. 显式输入

machine 写操作不应该静默依赖环境上下文。当前已强制：

```text
sub.render --name <name>
```

缺少目标返回 `EXPLICIT_INPUT_REQUIRED`，不会自动使用 active 订阅。

## 10. 权限

machine 不自动 sudo。需要特权时返回 `PERMISSION_REQUIRED`，由调用方决定是否重新以合适权限执行。
